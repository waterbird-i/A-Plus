## 2. 统一原则（18 个状态共用，规格卡不再重复）

### 2.1 可读性下限（这是最关键的一节）

**先看一个必须先承认的事实**：`answer_chain.csv` 里 35 道题的答案**长度极短**。

| 答案长度 | 例子 | 数量（估算） |
|---|---|---|
| 1 字符 | `白`、`C`、`静`、`2`、`3`、`1` | 约 14 道 |
| 2 字符 | `下课`、`21`、`102`、`抬头` | 约 5 道 |
| 3–4 字符 | `1978`、`0601`、`0713`、`exam` | 约 9 道 |
| 5+ 字符 | `厚德　笃学`、`10:20`、`invigilator`、`honest`、`9 月 1 日` | 约 7 道 |

> **所以「至少露出 3 个字符」这条直觉规则是错的**——对 14 道 1 字符答案的题，它物理上不可能成立。
> **可读性下限必须按答案长度分档。** 以下三档即验收标准。

| 档 | 触发条件 | 可读性下限（硬性） | 允许的遮挡类型 |
|---|---|---|---|
| **档 A** | 答案长度 **1–2 字符** | **遮挡不得削减答案本体的可读字符数**。允许遮挡答案的**上下文**（表格线、页眉、相邻行、页脚），但不许削掉答案笔画。若为全遮挡型，必须给出**周期性可读窗口**：窗口 ≥ **2.5 s**，间隔 ≤ **40 s** | 类型 II（时序窗口）、类型 III。**禁止类型 I 削减答案本体** |
| **档 B** | 答案长度 **3–4 字符** | 至少露出 **2 个连续字符**，其中**含前 2 位**（年份的前 2 位 / 考号的前 2 位）；露出部分必须能把候选集合收敛到 **≤ 3 个** | 类型 I / II / III |
| **档 C** | 答案长度 **≥ 5 字符** | 至少露出 **max(3 个完整字符, 60% 字符数向上取整)**；**必须是连续段**（不允许 `_0_1` 这种中间挖空） | 类型 I / II / III |

**三条配套铁律**（不分档）：

1. **遮挡边界必须落在字与字之间。** 因为答案文本是**预排版贴图**（5.5.5：呈现文本不走字符串），"被挡住一半"在实现上就是**贴图被 UV 区域裁掉**。若遮挡边界切在字身上，玩家看到的就是半个字——**那不是遮挡，那是猜谜**。允许误差 **±2 px**（贴图分辨率下）。真实几何遮挡（书包、身体）切在字身上时，**必须保证换角度后该字符能完整露出**（见铁律 2）。
2. **视差铁律：凡是"换角度能解"的遮挡，遮挡物必须有真实厚度或与答案表面分离。** 平面 decal 贴在答案表面（0 厚度）视差为零 → 换角度毫无变化 → **不可解**。硬性要求：遮挡层与答案表面的**法向间距 ≥ 2 mm**（世界尺度），或遮挡物本身是真实网格。唯一的例外是 `GlassGlare`（它天生视角相关，靠 Fresnel 而不是视差）。
3. **禁止唯一解要求玩家违反规则。** 不能出现「只有抬头才能看清」这种唯一解法——抬起视线必须是**可选代价**，不是唯一路径。（`q.fill.22` 的答案就是那条杀死你的规则，它的可读性必须最宽松：见卡 12。）

### 2.2 遮挡是「延迟」不是「否决」

对照 4.3 的原文：**「让同一道题每次的获取路径长度不同（有时秒答，有时要绕 3 步）」**。

| 规格 | 数值 | 说明 |
|---|---|---|
| 一个遮挡允许让玩家**最多多花几步** | **≤ 3 步** | 与 4.3 一致。超过 3 步 → 这个遮挡状态过强，要调窗口时长或残留量 |
| 遮挡允许造成的**最大总时长惩罚** | **≤ 25 s**（单题） | 超过 25 s 就是"否决"，会毁掉 8–12 分钟/轮（8.1）的节奏 |
| **绝不允许** | 遮挡使某题在本轮**完全无解** | 唯一的例外是 `MissingPage`（缺页），且它必须**当场改判到该题落位池的另一个源**（明确告知玩家：换源，见卡 18） |

**这条是"延迟"与"否决"的唯一分界线**：玩家在遮挡下永远有事可做（换角度 / 等 / 擦 / 听 / 借反光 / 换源）。

### 2.3 遮挡必须可解（解法清单，18 个状态只从这 6 类里选）

| 解法 | 说明 | 何时可用 | 是否跨源 |
|---|---|---|---|
| **换角度** | 利用视差 / 掠射角 / 反射角 | 遮挡物与表面有分离（铁律 2） | 否 |
| **等 NPC 挪动** | 前桌的身体、手臂、老师的翻页 | **他的行为是老师位置的函数（4.3 第 4 步）** | 否 |
| **借橡皮金属反光看倒影** | 唯一一个"用别的物件解决遮挡"的解法 | 已在 `answer_chain` 里出现（`q.fill.01` 的 `cross_source`） | **是**（`eraser`） |
| **听** | 靠音频的频段 / 韵律补全 | 只对 `broadcast` 有效 | 否 |
| **换到该题的另一个落位池** | 同题换个源 | 落位池 ≥ 2 个时永远可用（8.2 强制 2–4 个） | 否 |
| **无解 → 只能换源** | 唯一一例：`MissingPage` | 见卡 18 | 否（换源，不是跨源） |

> **注意「换到另一个落位池」是保底解法。** 这保证了 2.2 的「不否决」在任何情况下都成立：**哪怕遮挡做坏了，玩家还有一条路**。所以：遮挡做得再难也不能让玩家卡死——这是数据侧的 2–4 落位池规则给美术上的免费保险。

### 2.4 ★ 遮挡（看不见）vs 不可信（看得见但是假的）——必须是两种体验

这是本文档最容易被做错的地方。**4.4 说的是"内容可能是假的"，遮挡说的是"内容看不见"。这两件事在画面上必须一眼可分。**

| 维度 | **遮挡**（物理上看不见） | **不可信**（看得见但内容是假的） |
|---|---|---|
| 玩家心里的话 | 「我看**不到**」 | 「我看到了，但**不知道是不是真的**」 |
| 画面证据 | 有**明确的遮挡物**：书包、纸、灰、手臂、身体、雨 | 内容**完整、清晰、无遮挡**——甚至比周围更清楚（因为它被认真写过） |
| 接触阴影 / 物理 | **必须有接触阴影**（遮挡物压住表面） | 无，是平面的 |
| 时间行为 | **等待会有回报**（窗口会来、灰会落、纸角会被风吹起） | **等待不会让它变真**。唯一的解法是跨源核对（`cross_source`） |
| 在数据上 | `answer_chain.occlusions` | **`answer_chain` 目前没有对应列**（见 7.2） |
| 玩家能学到的 | 「换个角度/等一下」 | 「不能只信一个源」 |
| 两者同时出现时 | **必须时序分离**：先解遮挡（拿到文字），再浮现"可疑"。**绝不允许同一眼既是看不清又是可疑**——那会让玩家直接放弃这个源，退化成"否决" | |

**★ 与 `q.fill.16` 的关系**：`q.fill.16` 同时挂了 `被身体挡住` / `被手臂压住`（遮挡）与 `★前桌可能故意写错（4.4）`（不可信）。**这不是数据错误，但它强制了一条实现规则**：

> **同一个源上的"遮挡"与"不可信"必须错峰揭示**（复用 2.4 死亡退化的「不同步揭示」技术）：
> 第 1 步：解遮挡（换角度 / 等他挪动）→ 拿到「C」；
> 第 2 步：**在你已经写下 C 之后**，让"可疑"浮现（例如：你回头看时，那道题旁边有一处被擦改过的痕迹）。
> **顺序不能反。** 反了就是同时在说"看不到"和"可能是假的"。

### 2.5 ★ 与 2.1 管道视野的叠加（四条硬规则）

2.1 的原文：「**环视 = 视野收窄成管道：中心清晰，周边全黑**」「**周边全黑不是遮罩，是"你的余光不可信"**——边缘的画面可以轻微扭曲/滞后」。

遮挡**全部发生在环视状态里**，所以必须和管道视野同时成立：

| # | 硬规则 | 理由 |
|---|---|---|
| 1 | **答案的可读区必须落在管道视野中心（半角 ≤ 25°–30°）内** | 管道视野的中心才是"清晰"的那一块（2.1）。答案落在边缘 = 无论有没有遮挡都读不到 |
| 2 | **遮挡物的轮廓必须落在半亮区可见** | 玩家必须能**看见"被什么挡住了"**，否则他不知道该往哪偏。遮挡物的剪影对比度要够（对着后方全黑的背景时，遮挡物需要边缘光/轮廓光） |
| 3 | **两者作用层不同，不得互相放大** | 管道视野 = 后期处理（暗角 + 边缘滞后/扭曲）；遮挡 = 几何 + 材质 + 音频。**验收时必须在"环视开启"的状态下测**——在"卷子"状态里答案源根本不在视野内，测不出问题 |
| 4 | **管道视野不得把遮挡物的接触阴影抹掉** | 暗角会让边缘整体压暗，接触阴影会消失 → 遮挡看起来像"浮"在表面上（破坏 2.4 的区分）。接触阴影（AO）要走**自己的通道**，不受暗角影响 |

### 2.6 遮挡状态必须持久（不随切换视线状态刷新）

| 规格 | 说明 |
|---|---|
| 状态持久性 | 抽到的遮挡**在本场考试内不变**。不允许"回卷子再抬头就变干净了"——那样玩家可以靠反复切换白嫖（破坏 4.3 的"绕 3 步"） |
| 相位推进 | 但**时序窗口的相位在你没看的时候要继续走**（用 timer）。允许玩家"蒙对"时机，这正是 4.3 要的"有时秒答" |
| NPC 类遮挡的相位 | `BodyBlock` / `ArmPress` 的相位**由老师当前所在排驱动**（4.3 第 4 步：「他什么时候挪？取决于老师现在在看哪一排」），不是纯随机 timer |
| 累积性 | `BreathMask`（被呼吸声盖住）**不是持久状态，而是暴露时间的函数**（≥ 阈值才出现）。这是唯一的例外，见卡 14 |

### 3.2 `OcclusionPresenter` —— 单一组件

**一个组件，不做 18 个组件。** 理由：18 个状态里有 15 个共享同一套执行流程（取状态 → 找遮挡物 → 应用遮罩 → 定时/相位 → 校验可读性），差异只在**遮挡物与遮罩参数**，那应该是资产与数据，不是代码分支。

```
OcclusionPresenter  (挂在每个"可被遮挡的答案源"上，或一个管理器持有全部)
├── OcclusionState state          // 只读：由关卡抽取写入（4.3 第 4 步）
├── Transform occluderRoot        // 遮挡物的父节点
├── OcclusionProfile profile      // ScriptableObject：该状态的参数（见下表）
├── float phase                   // 时序窗口相位（未观察时也推进）
└── Methods
    ├── Apply(OcclusionState s)                     // 装配遮挡物 + 设参数
    ├── Tick(float dt, Context ctx)                 // phase 推进；NPC 类读 ctx.teacherRow
    ├── bool IsReadableNow()                        // 供暴露计时/提示使用
    └── OcclusionReadability Validate(Profile p)    // 见 3.4：抽到不能读的档 → 回退 None
```

**对外只暴露两件事**：`State`（给存档/日志）与 `IsReadableNow()`（给其它系统一个"现在能读"的判定）。**其它系统不允许直接读遮挡物**。

`OcclusionProfile`（ScriptableObject，每状态一个，共 18 个）字段：

| 字段 | 用途 | 例（`ByBag`） |
|---|---|---|
| `domain` | `Geometry` / `Material` / `Shader` / `Audio` / `Procedural` / `Data` | `Geometry` |
| `occluderPrefab` | 遮挡物 | 书包网格 |
| `normalOffsetMm` | 与答案表面的法向间距（**铁律 2，≥ 2 mm**） | 60 mm（书包有厚度） |
| `maskRectUV` | 字符削减型的裁切区域（**边界必须落在字间**） | 右侧 1/4 区 |
| `readabilityTier` | 该状态允许的档：`A/B/C` 位掩码 | `B\|C`（不允许档 A） |
| `windowOnSec` / `windowOffSec` | 时序窗口（全遮挡型必填） | —— |
| `crossSourceHint` | 是否需要跨源（对应 `answer_chain.cross_source`） | 需要（`eraser`） |
| `audioBus` | 音频掩蔽总线（仅类型 III） | —— |
| `verifyNote` | 验收用的可测量值（见每张卡） | 「左偏 15° → 露出 3 字符」 |

### 3.3 遮挡贴图 / 材质变体 / 视差（怎么让它"可施工"）

| 手段 | 用在哪些状态 | 规格 |
|---|---|---|
| **真实几何遮挡（首选）** | `ByBag` `NewSheet` `BodyBlock` `ArmPress` `ClosedLedger` `TornCorner` `MissingPage` `FanSpeed` | **用真实网格，不用面片。** 书包必须是**体积网格**（有厚度、有下沿阴影），因为"换角度"全靠它。面片 = 视差为零 = 不可解（铁律 2） |
| **平面遮挡 = 薄板 + 分离** | `PasteBleed` `ChalkDust` `HalfErased` `ChalkOverwrite` `Condensation` `RainStreak` | 这些天生贴在同一表面（灰在玻璃上、糨糊在纸上）。做法：**同一表面 + 一层厚度 2–5 mm 的透明板**，或（更省）**在贴图上做 mask 但把 mask 的 UV 偏移做成视角的函数**（伪视差）。**伪视差必须能在 15° 侧偏下改变 ≥ 20% 的 mask 区域**，否则视为不可解 |
| **视角相关 shader（唯一不用视差的状态）** | `GlassGlare` | **panning 的法线贴图 + 视角相关的 Fresnel**：`_Glare = pow(1-dot(N,V), p)`，`p` 控制"反光吃掉多少"。偏头时 Fresnel 变化 → 反光移动 → 字露出来 |
| **音频掩蔽（不是降音量）** | `CicadaMask` `BreathMask` | 见卡 13 / 卡 14。**严禁用"把广播音量调低"实现**——那是纯否决 |
| **程序化动画** | `FanSpeed` `NewSheet`（风掀纸角）`ArmPress`（抬笔） | 参数化、可复现（随机种子来自关卡种子）。**不做手 K 动画**（8.4：小团队无动画预算） |

**贴图规格**：答案源上的文字是**预排版贴图**（5.5.5），所以遮挡是对贴图的操作。

| 项 | 规格 |
|---|---|
| 答案贴图分辨率 | 每源一张 **2048×2048**（文字区域至少 1024 px 宽）；红旗/红榜这类窄长物件可 2048×512 |
| 文字落位 | 由关卡设计给**字符级 bounding box**（每字符一个矩形），落进 `answer_chain` 之外的编辑器数据 → `OcclusionPresenter` 靠它实现"边界落在字间"与"校验残留字符数" |
| mask 精度 | 8-bit 足够；但**字符级 mask 建议用几何（遮罩矩形）而不是笔刷贴图**——因为可读性下限要**可验证**（程序能算"剩几个完整字符"），笔刷 mask 无法自动校验 |
| 材质变体 | 每状态一个 `Material Variant`（共用母 shader `A+/OcclusionMask`，18 个变体）。**不要 18 个独立 shader** |

### 3.4 与 4.3「随机抽一个遮挡状态」的对接

数据侧已经定好「哪道题允许哪些遮挡」，组件**只读枚举**。抽取流程与责任边界：

```
关卡抽取（数据侧，已有）
  1. 抽题（35 道，demo=y 优先）
  2. 从题的 pools 里随机抽一个源
  3. 从源的 occlusions 里随机抽一个遮挡状态（或 None）        ← 4.3 第 4 步
  ↓ 传给 OcclusionPresenter
  4. Validate(): 该状态允许的档 是否覆盖 本题答案长度档？
        ├─ 覆盖 → Apply(state)
        └─ 不覆盖 → **回退为 None 并重抽一次**（仍不覆盖则 None）
  ↓
  5. Apply(state) → 装配遮挡物 → Tick() 推进相位
```

> **第 4 步是本文档新增的、数据侧没有的规则。** 原因见 2.1：`answer_chain.occlusions` 是静态列表，**它不知道答案有多长**。给它一个 1 字符答案（`白`、`C`、`静`）却抽到 `TornCorner`（`readabilityTier = B|C`）→ 会直接违反可读性下限。
> **回退为 `None` 是唯一安全的默认行为**（2.2：「偶尔秒答」本来就是设计，见 4.3）。**不要**改成"重抽另一个状态"——那会让遮挡状态分布偏移。
> 这条规则要不要落进 `validate_chain.js` 由数据侧决定（本文档只提出，见 7.2）。

**与暴露时间 / 管道视野的接口**

| 接口 | 方向 | 说明 |
|---|---|---|
| `ctx.teacherRow` | 输入 | NPC 类遮挡的相位来源（4.3 第 4 步：他的行为是老师位置的函数） |
| `ctx.exposure` | 输入 | `BreathMask` 的触发与强度（2.1：呼吸声就是暴露计时器） |
| `ctx.pipeVisionActive` | 输入 | 管道视野是否开启（2.5 硬规则 3） |
| `IsReadableNow()` | 输出 | 供 UI 无关的提示/引导、以及**自动验收测试**使用 |
| `OcclusionHint` | 输出（可选） | 一个极轻的世界内提示（例如纸角被风吹起的**声音**）——**不是 HUD**（零 HUD，8.1） |

### 7.3 ★ `fan` 的「转速不对」：一个信号不能同时是"威胁线索"和"遮挡状态"

- **2.2 说**：异视的听觉线索是「**吊扇转速不对**」——它是**你必须抬头**的信号。
- **2.2 又说**：异视的正确应对是「**抬头。直视它，直到它先移开**」→ 异象消失。
- **`sources.csv` 说**：「转速不对」是 `fan`（吊扇）的**遮挡状态**。

**这不是矛盾的表述，而是一个可用的设计**（也是本文档的裁决建议）：

| 层面 | 规格 |
|---|---|
| **听觉层** | 转速不对 = 异视线索（2.2 不变）。**必须保持** |
| **视觉层** | 转速不对 = 扇叶的遮挡节奏（本卡 15） |
| **两者关系** | **一起出现**：异视出现 → 转速不对（听得见）→ **同时**扇叶遮挡变强（看得见） |
| **为什么这是好设计** | 玩家学到：**"听见转速不对"就等于"我现在看不清吊扇上的东西"** → 而解决它的唯一办法是**抬头直视**（驱散异视）→ 遮挡消失。**这是唯一一个"只有正确应对威胁才能解开"的遮挡**，是把 2.2 和 4.3 缝在一起的机会 |
| **仍然需要人定的** | 转速参数是否共用一个（听觉 = 视觉同一变量）还是两个独立参数？**建议：两个独立参数，但由同一个异视状态同时驱动**（避免"听觉已经恢复但视觉还在挡"的不一致） |

### 7.4 ★ 4.4 的一处口径问题（建议主文档修订）

**4.4 的表**把「黑板残字」的**不可靠原因**写成：

> 「上一节课留下的，**被擦掉了一半**」

**这与 4.4 自己的立论冲突。** 4.4 的立论是「**不是所有信息源都可靠**……你在判断谁在骗你」，即**看得见但内容是假的**；而"被擦掉一半"是**物理上看不见**，属于遮挡（本文档第 2 节）。

| 建议修订 | 内容 |
|---|---|
| 黑板残字的**不可信**原因改为 | 「**上一节课留下的**——它与本场考试的**年份/科目/单位制不一致**（例如英语课的板书写着 1998 年的年份）」，即内容层面的不匹配，而不是物理缺失 |
| 「被擦掉一半」 | 归入**遮挡**（本文档卡 5），与不可信**分开** |
| 这条修订的重要性 | 不修的话，实现者会照 4.4 表把"擦掉一半"做成"内容可疑"→ **遮挡与不可信在同一个像素上同时成立 → 2.4 的区分崩塌** |
| 与 6.3 的配套 | 黑板上的真正"不可信"应该是 6.3 的「**黑板上的字多一笔**」（看得见但是假的）——**"多一笔"= 不可信，"擦掉一半"= 遮挡**，两者绝不同时出现在同一行 |

### 7.5 老师的写字行为（影响卡 6 / 卡 10）

- `ChalkOverwrite`（被下节课板书覆盖）在逻辑上要求"**有下节课的板书**"，而 8.3 明确不做老师的写字动画、老师几乎不位移（1.3 冲突 3）。
- **裁决建议**：`ChalkOverwrite` 的板书改为"**进场时就存在**"（上一节课的残留），**老师永不书写**。这样 `q.fill.14`（另一个池是 `back_wall`）也说得通。
- **仍需人定**：新板书的内容（哪一科、写什么）——这是**文案资产**，属于 8.3-3「写死全部恐怖文本」的范畴。

### 7.6 同一源上两个遮挡状态能否叠加

| 组合 | 是否允许 | 理由 |
|---|---|---|
| `flag` 上 `ByBag` + `PasteBleed`（书包 + 糨糊） | ⚠️ **未定** | 物理上可以同时存在（书包压着湿纸），但**两个削减叠加会违反可读性下限** → **建议：同一源同一时刻只允许一个削减型状态** |
| `honor_roll` 上 `NewSheet` + `PasteBleed` | ⚠️ **未定** | 同上（卡 7 的咬合里提到"允许叠加"，但**叠加会双倍削减**——**修正为：不允许同时削减，但允许"新榜 + 糨糊"共存于同一张贴纸**） |
| `desk_front` 上 `BodyBlock` + `ArmPress` | ⚠️ **未定** | 两者是同一个 NPC 的不同部位。**建议互斥**（否则玩家无法归因"他在动还是他挡住了"） |
| `ledger` 上 `ClosedLedger` + `WrongPage` | ❌ **禁止** | 逻辑上互斥（合上就没有页） |

> **统一规则的裁决建议**：**同一源、同一时刻，最多一个"削减可读性"的状态。** 理由回到 2.2：**两个削减叠加 = 步数翻倍 = 从"延迟"变成"否决"。**

### 7.7 ★ 与本文档编写期间新增的 `occlusion_ids.csv` 的两处口径冲突

本文档 3.1 引用的 `Assets/Data/occlusion_ids.csv` 是**本文档编写期间由他人新增**的（18 行，`id`/`kind`/`extra_steps`/`resolvable`）。18 个状态一一对应，但有 **2 行**与本文档规格卡的"可解性"不一致：

| # | 状态 | `occlusion_ids.csv` | 本文档卡 | 冲突的实质 |
|---|---|---|---|---|
| 1 | 被新榜覆盖 `covered_by_new` | `resolvable=n`、`extra_steps=2`（旧榜被盖住 ⇒ 信息不可得 ⇒ 换落位池） | 卡 7：**y**，靠"风掀纸角"的时序窗口（1.5–3 s）等出来 | `n` 会让它退化成"否决 + 换源"；`y` 多花约 3 h（风掀程序化）但保住 4.3 的"绕 3 步"味道 |
| 2 | 被撕掉一角 `torn_corner` | `resolvable=n`、`extra_steps=2`（缺的那一角就是答案 ⇒ 换落位池） | 卡 12：**y**，靠"背面压痕（拓印）"读回来 | ★6.2 说隐藏规则第 5–7 条写在**规则墙背面**——"撕掉的一角正好在能看背面的位置"是白送的恐怖点，做成 `n` 会丢掉它；且 `q.fill.22`（答案＝「抬头」，那条杀死你的规则）变成"必须换源"的题，与 2.2 体验冲突更大 |
| 3 | 缺页 `missing_page` | `resolvable=n` | 卡 18：**n** | **一致**，无需裁决（本文档 2.2 已把它列为唯一允许"无解 → 换源"的先例） |

> **裁决（已执行）：采纳 `resolvable=n`。** `covered_by_new` / `torn_corner` / `missing_page` 三个状态一律按「**该源上不可得 ⇒ 当场改判到该题落位池的另一个源**」处理。
>
> 理由：① 它在 4.3 的语义里**仍然是延迟、不是否决** —— 每题都有 2–4 个落位池，玩家永远有第二个地方可看，所以不违反 2.2 的原则；② 省掉「风掀纸角」与「背面拓印」两套程序化实现（各约 3 h）；③ 三行口径统一，代码只需要一条规则。
>
> **代价（明确记录，不掩盖）**：卡 12 丢掉「规则墙背面」这个白送的恐怖点；`q.fill.22`（答案＝「抬头」，那条杀死你的规则）从「看背面」退成「换一个源」。将来若要反悔，改动是两行数据（`resolvable` 改回 `y`）+ 卡 7 / 卡 12 的验收标准，成本各 +3 h。

> **同一批新增文件的一个缺陷（已修，留作教训）**：`Assets/Data/enum_labels.csv` 的 `label` 列曾被**二次编码读坏**（UTF-8 → GBK → UTF-8）。根因不是编辑器，而是 **PowerShell 的 `Get-Content` 在没有 UTF-8 BOM 的文件上会按系统 ANSI（中文 Windows 上是 GBK）解码**；而 GBK 是双字节编码，会把紧随其后的换行也当成尾字节吃掉 —— 于是文件既乱码又**丢掉行结构**。已修（重写文件，并把 `Assets/Localization` 与 `Assets/Data` 下全部 CSV 正规化为 **UTF-8 BOM + CRLF**），并加了两道防线：① 原型自检 `every csv carries a utf-8 BOM (Excel/WPS/PowerShell must not garble chinese)`；② 项目约定「改 CSV 用编辑器或 Node，不要用 PowerShell 的 `Get-Content`/`Set-Content` 往返」。同表的 `id` 列（ASCII）当时未受影响，所以它作为枚举桥一直可用。
