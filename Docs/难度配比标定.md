# 难度配比标定与题库规模 ——《A+》实测记录

> [!info] 这份文档回答两个问题
> 1. **8.2 写的「35 道撑不了一局 8–10 道 × 无限轮次」到底差多少？** → 第 3、4 节，有反推公式。
> 2. **`difficulty` 那一列的配比到底怎么定？** → 第 5 节，三种分配策略的实测对比。
>
> 对应设计文档：**4.3 随机化方案** · **8.2 内容量清单** · **8.4 为什么这套规格对小团队可行**。

## 0. 先说清楚这份文档**不是**什么

本文的数字来自**命令行原型**（`Tools/APlusProto`）把 4.3 的抽题流程跑了 **4000 轮**的统计，
**不是玩测数据**。所以：

| 是 | 不是 |
|---|---|
| 「题库规模够不够」「配比能不能兑现」的**结构性**结论 —— 这类问题靠模拟就能定死 | 「第几次开始不吓人」的手感 —— 那必须真人连死 16 次来标定（见设计文档 8.3-4） |
| 「每道题平均会被看到几次」的算术 | 「玩家实际花多少秒拿到一个答案」—— 原型里的**动作步数 / 暴露分是透明模型**，不是实测耗时 |
| 三个遮挡状态、两个通道的**占用率**（美术投入该往哪放） | 遮挡的可辨性、点阵屏可读性等**真机视觉**问题 |

**动作步数 / 暴露分模型**（写在这里，因为它决定了第 5 节的所有对比）：

```
动作步数 = 1（离开卷子进入环视 / 拿起手机）
         + 该遮挡状态的 extra_steps（0–2，见 occlusion_ids.csv）
         + 1（若该题需要跨源拼合）
         + 1（若落在手机通道上）
         + 2（若抽到「该源上不可得」的遮挡 ⇒ 必须换到另一个落位池）
         + 1（退回卷子作答）

暴露分   = 该源的 risk 权重（无0/低1/中2/高3/极高4/最高5）
         + 0.5 × extra_steps
         + 1（跨源） + 1.5（手机） + 1（换源）
```

> 这套权重是**我定的**，不是设计文档里的数字。它的用途是让三种配比策略**可比较**，不是当作难度绝对值。
> 真机标定时应当用真人耗时替换它 —— 这是本表最大的未验证项。

## 1. 复现命令

```powershell
# 完整跑（数据面 + 26 条断言 + 硬编码扫描 + 模拟 + 配比扫描 + 分配策略对比）
Tools/APlusProto/bin/APlusProto.exe all --rounds 4000 --size 9 --mix 3,3,3 --mode jitter

# 只跑分配策略对比（这就是第 5 节的表）
Tools/APlusProto/bin/APlusProto.exe modes --rounds 4000 --size 9 --mix 3,3,3

# 换题库规模再跑一遍（扩题后应该重跑这一条）
Tools/APlusProto/bin/APlusProto.exe sim --rounds 4000 --size 9 --mix 3,3,3
```

固定 `--seed 20260101`；抽题用**自带确定性 PRNG**（不是 `System.Random` —— 它在 .NET 与 Unity 的 Mono/IL2CPP 上序列不同，同一个种子抽不出同一张卷子）。

## 2. 指标定义（本文所有表都用这四个词）

| 指标 | 定义 | 为什么它是关键 |
|---|---|---|
| **coupon collector** | 「题库里每一道题都至少出现过一次」所需的轮数 | **过了这个轮数，后面每一轮都只是已经见过的题的重排** —— 复读感就是这么来的。这是「题库够不够」的硬指标 |
| **carry-over** | 相邻两轮重复出现的题数（理论值 ≈ 每轮题数² / 题库规模） | 直接决定「这一轮和上一轮像不像」 |
| **χ²/df** | 各题出现频次的卡方统计量 / 自由度（1.0 = 完全均匀） | 磨损是否均匀。>1 意味着有些题被反复消费、有些被冷落 |
| **每轮易题波幅** | 每轮「易」题数的 min / max / 平均绝对偏差 | **「每轮手感一样吗」的量化代理** |

| | 扩题前 | 扩题后 |
|---|---|---|
| 题库 | 35 道 | **62 道**（Demo 可用 **60** 道：`q.fill.20/21` 是 `demo=n`） |
| 难度池 | 易14 · 中12 · 难9 | **易22 · 中21 · 难19**（Demo 池 易22 · 中20 · 难18） |
| 通道 | 环境27 · 手机6 · 混合2 | 环境47 · **手机13** · 混合2 |

| **coupon collector** | **16.8 轮** | **29.6 轮**（+76%） |
| **carry-over** | 2.4 题/轮 | **1.4 题/轮** |
| **χ²/df** | **37.1** | **5.2** |

### 3.1 原型在这里抓到的三个真问题（已修）

| # | 问题 | 怎么发现的 | 修法 |
|---|---|---|---|
| 1 | `q.fill.20` / `q.fill.21` 的落位池是 `fan\|door_glass\|window`，而**三个源全是 `demo=n`** → Demo 里这两题**没有合法落位** | 加了「demo=y 的题至少有一个 demo=y 的落位源」这条检查 | 两条题改 `demo=n`（内容本来就依赖正式版资产），不给它们编造落位池 |
| 2 | `eraser`（你自己的橡皮／笔袋夹层）被建模成答案源，却**不在任何落位池里** → 4000 轮从未被抽中，等于白做 | 模拟统计「从未被抽中的源」 | 让 3 道新题（`q.fill.39/40/41`）把 `eraser` 放进落位池——答案必须是「你会在进场前抄在橡皮上的东西」 |
| 3 | `q.fill.23` 的 `cross_source` 写成了 `抬头次数（同一张卷子的抬头·第 N 次模拟考试）`——**夹带说明文字，代码没法解析** | 加了「cross_source 必须是已知源 id」这条检查 | 改成裸 id `paper_self`，说明文字移进 `notes` |

**这就是「先把这 35 道跑通再扩」的全部价值**：三个问题都是**数据/建模**问题，靠读文档看不出来，一跑就露。
如果先扩到 60 道再跑，这三个坑就会被复制 27 遍。

## 4. 「无限轮次」到底需要多少题

没有哪个有限题库能撑真正的无限轮次。真问题是：**你希望「不重复感」撑多少轮？**

coupon collector 近似式 `N·(ln N + 0.5772) / 每轮题数`，每轮 9 道：

| 题库 | 全部题目都见过所需轮数 | 玩满 50 轮时，每道题平均被看到 |
|---|---|---|
| 35 | ~16 轮 | **12.9 次** |
| 45 | ~22 轮 | 10.0 次 |
| **60（当前 Demo）** | **~30 轮** | **7.5 次** |
| 62 | ~32 轮 | 7.3 次 |
| 80 | ~44 轮 | 5.6 次 |
| 100 | ~58 轮 | 4.5 次 |
| 130 | ~79 轮 | 3.5 次 |

**结论：**

- **当前 62 道（Demo 60）把「不重复感」从 16 轮推到 30 轮**，是原来的一倍。对 8–12 分钟一局、设计上就要「复读」的游戏，这个量级是够用的。
- **如果你的目标是不重复感撑到 50 轮，需要约 87 道**（`N` 满足 `N(ln N+0.5772)/9 = 50`）。→ 下一批扩题的规模建议 = **再 +25 道**。
- **每多 20 道，只多买约 12 轮**（对数增长）。所以「扩题库」不是无限有效的对策 —— **2.5「复读显式告诉玩家」和 7.1「每场换监考 + 异象收尾」才是撑住长线的真正手段**，题库只是把它们垫平。这一点值得写进 8.4。

## 5. 配比标定：三种分配策略（这是本次的核心结论）

同一个题库（60 道 Demo）、同样 9 道/轮、4000 轮，只换**分配策略**：

| 模式 | 每轮易题 min/max/偏差 | 配比兑现 | 手机题/轮 | 动作步数/轮 | 暴露分/轮 | χ²/df | coupon collector |
|---|---|---|---|---|---|---|---|
| `quota` 固定配额 | **3 / 3 / 0.0** | 0 轮欠配 | 2.1 | 26.3 | 30.4 | 4.8 | 29.8 |
| `jitter` 配额+抖动 1 | **2 / 4 / 0.7** | 0 轮欠配 | 2.1 | 26.3 | 30.5 | 5.2 | 29.6 |
| `weighted` 按难度加权、不配额 | **0 / 8 / 1.1** | — | 2.2 | 26.3 | 30.5 | 4.8 | 29.7 |

**读法：**

- **固定配额（`quota`）= 每轮组成完全一样。** 偏差 0.0 意味着**第 1 轮和第 100 轮的难度构成一模一样** ——
  这恰好就是你担心的「**每轮手感一样**」，而且比预想的更严重：它不是「差不多像」，是**逐字相同**。
- **加权不配额（`weighted`）= 波动过大。** 易题数能落到 **0 或 8**（9 道的一轮里），
  也就是「整轮全是难题」或「整轮全是易题」都会发生。恐怖游戏偶尔来一轮这样的是惊喜，**当成常态就是失控**。
- **配额+抖动 1（`jitter`）= 推荐。** 每轮易题在 **2–4** 之间浮动，平均偏差 0.7，
  难度预算仍然受控（0 轮欠配），而每轮**不是同一个组成**。

> **推荐参数（可以直接抄进代码）：**
> `mix = 3,3,3`（每轮 9 道）· `mode = jitter` · `jitter = 1` · `noOcclusionProbability = 0.45`
> 8 道/轮用 `3,3,2`；10 道/轮用 `3,4,3`（实测见 `--sweep`，全部 0 轮欠配）。

### 5.1 磨损均匀有一个前提条件（容易被忽略）

χ²/df 从 37.1 降到 5.2，但**没有降到 1.0**。原因不是 bug：

- 固定配额每轮从每个池抽**同样多**的题（3 道），但池的大小不同（22 / 20 / 18）
  ⇒ 每道题被抽到的概率 = 3/22 : 3/20 : 3/18 = **1 : 1.10 : 1.22**
  ⇒ 难度池越小的那一档，题目被消费得越快。
- **想要 χ²/df → 1，两条路**（二选一）：
  1. **用 `quota` / `jitter` 时，让三个难度池大小尽量相等**（当前 22/20/18 已经接近，残差只有 1.22×）；
  2. **用 `weighted` 时，把权重设成与池大小成比例**（原型目前用配比当权重，所以没有自动均匀）。
- 下一批扩题的实操建议：**按当前的短板补，把三个池拉到等大**（易 +? / 中 +? / 难 +? 由扩题时的实际池大小决定）。

### 5.2 遮挡状态：美术投入该往哪放（实测占用率）

4000 轮 × 9 道 = 36000 次抽题的遮挡分布（去掉 25492 次「无遮挡」后的相对量级）：

| 状态 | 次数 | 一句读法 |
|---|---|---|
| `wiped_half` 被擦掉一半 | 2712 | 最常出现 —— 优先做，验证成本最高的是它 |
| `torn_corner` 被撕掉一角 | 1104 | |
| `glass_glare` 被玻璃反光吃掉 | 1031 | ★4.3 的原始示例，出现率够高，值得做视差 |
| `body_block` 被身体挡住 | 968 | 依赖 NPC 行为，成本高但出现率也高 |
| `covered_by_new` / `paste_bleed` | 685 / 685 | |
| `closed` / `arm_cover` / `cicada_mask` | 594 / 568 / 562 | |
| `wrong_page` / `breath_mask` | 421 / 328 | |
| `overwritten_board` / `schoolbag_half` | 293 / 282 | ★4.3 原文举的就是「被书包挡住一半」—— 出现率其实**偏低** |
| `chalk_dust` | 275 | |

## 6. 必须靠真人标定、本文定不了的部分

| 项 | 为什么定不了 | 怎么标定 |
|---|---|---|
| 「第几次开始不吓人」 | 是心理曲线，不是统计量 | 按 8.3-4：先定 `t = N/15`，内部测试连死 16 次，记录掉下来的那一次，反过来改 `t` |
| 动作步数的真实耗时 | 本文用的是权重模型 | 真人测：环视一次几秒、等 NPC 挪一次平均几秒、掏手机一次几秒；替换掉 `ExamRoundGenerator.Plan()` 里的两个公式 |
| `ComplyGraceSeconds = 0.6s` | 是原型假设值 | 真人测「看到警告到做出反应」的分布；太松则两难不成立，太紧则不可读（2.2 的边界） |
| 遮挡状态的可辨性 | 视觉问题 | 按 `Docs/遮挡表现规格.md` 的验收清单逐卡过 |
| 手机题的电池压力是否够 | 需要知道每道手机题的真实耗时 + 电量消耗曲线（5.4） | 拿到 2.1 道/轮这个数字后，用真机跑一轮看电量是否恰好构成压力 |

## 8. 一句话结论

> **题库 62 道够用了（不重复感 30 轮）；配比本身不该用固定配额，用 `3,3,3 + 抖动 1`。**
> 真正撑不住长线的不是题库，是**复读的呈现方式** —— 那是 2.5 和 7.1 的活。
> 而本次最值钱的产出不是这些数字，是原型抓到的**三个真实数据缺陷**（第 3.1 节）。
