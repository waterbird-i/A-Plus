# 关卡设计数据 ——《A+》答案链与答案源

> [!important] 这里放的是**数据**，不是文本
> 题干在 `../Localization/questions.csv`（走 String Table）。
> **答案、落位池、遮挡状态是关卡设计**，不是可翻译文本——所以它们在这里，用另一套 schema。
> 对应设计文档：**4.3 随机化方案** · **4.2 环境答案源清单** · **8.2 内容量清单**。

## 为什么分成两张表

| | `../Localization/questions.csv` | 本目录 |
|---|---|---|
| 内容 | 题干文本 | 答案 / 落位池 / 遮挡 / 难度 |
| 性质 | **文本** → 要进 String Table | **数据** → 关卡设计 |
| 谁改 | 文案 | 关卡设计 |
| 校验 | `validate.js` | `validate_chain.js` |

**混成一张表的代价**：题干一改（比如校训换一个字）就得动整行设计数据；而答案一调（比如把 3 改成 5）又会被当成文案变更。**两者变更频率和责任人完全不同。**

## 文件

| 文件 | 内容 |
|---|---|
| `sources.csv` | **答案源目录**（4.2 清单的数据化）：id / 名称 / 通道 / 位置 / 风险 / 是否 Demo / 允许的遮挡状态 |
| `answer_chain.csv` | **答案链**：每题的答案、合法落位池、跨源依赖、遮挡状态、难度 |
| `occlusion_ids.csv` | **遮挡状态枚举桥**：中文状态名 ↔ ASCII id / 类别 / extra_steps / 是否可解。**代码里不允许出现中文，所以这张桥是必需的**（18 行） |
| `enum_labels.csv` | **枚举标签桥**：difficulty / channel / answer_type / risk 的中文标签 ↔ ASCII id / 权重。让 C# 源码保持纯 ASCII（13 行） |
| `validate_chain.js` | 校验器（`node validate_chain.js`） |

### 编码（硬规则）

**所有 CSV 一律 UTF-8 with BOM + CRLF。** 不是洁癖：

> PowerShell 的 `Get-Content` 在**没有 BOM** 的文件上会按系统 ANSI（中文 Windows 上是 GBK）解码，
> 而 GBK 是双字节编码，会把紧随其后的**换行也当成尾字节吃掉** —— 本目录的 `enum_labels.csv` 与
> `Assets/Scripts/APlus/HardcodedStringScanner.cs` 都因此损坏过一次（修复记录见 `Docs/遮挡表现规格.md` §7.7）。

**改这两张表请用编辑器或 Node，不要用 PowerShell 的 `Get-Content`/`Set-Content` 往返。**
原型自检里有一条 `every csv carries a utf-8 BOM` 守着。

## answer_chain.csv 列

| 列 | 说明 |
|---|---|
| `q_id` | **就是 String Table 的 key**（`q.fill.01`）。校验器会与 `questions.csv` / `world_en.csv` 做**双向参照完整性**检查 |
| `answer_type` | `固定` ｜ `动态`。**动态 = 答案随轮次/年份系统变化** |
| `answer` | 答案本身。动态答案写清**由什么驱动** |
| `pools` | **合法落位池**（`\|` 分隔）。设计文档 8.2 要求 **2–4 个** |
| `cross_source` | **还需要读的第二个源**（跨源拼合），不需要时留空 |
| `occlusions` | 允许的遮挡状态。必须是所落位池的**并集的子集** |
| `difficulty` | `易` ｜ `中` ｜ `难` |
| `demo` | `y` ｜ `n` |
| `notes` | ★ 标出与哪条机制咬合，改动前先看设计文档 |

### `cross_source` 的写法（约定）

**必须是源 id**，多个用 `|` 分隔。**允许带括号说明，但 id 必须写在最前面**：

```
paper_self                       ✅ 裸 id
eraser（借橡皮金属反光看被挡住的那一半）   ✅ id 在前，说明在后（老行的写法，兼容）
抬头次数（同一张卷子的抬头·第 N 次…）     ❌ 没有 id —— 原型会报错
```

说明文字属于 `notes`，不属于这一列。原型的 `StripDescription()` 会剥掉括号后校验 id 是否存在于 `sources.csv`。

### Demo 落位可达性（硬规则）

**`demo=y` 的题，落位池里至少要有一个 `demo=y` 的源。** 否则这道题在 Demo 里没有合法落位。

这条规则是**原型跑出来的**：`q.fill.20` / `q.fill.21` 的池是 `fan|door_glass|window`，三个源全 `demo=n`
→ Demo 里这两题无处可落。修法是**把这两条题改成 `demo=n`**（它们的内容本来就依赖正式版资产），
而不是给它们编造落位池——后者会违反 4.3「答案永远藏在合理的地方」。

**副作用（已确认，不是意外）**：`转速不对` / `水汽` / `雨痕` / `缺页` 四个遮挡状态唯一的归属源都是
`demo=n`，所以它们**在 Demo 中恒为 0 次**（原型实测）。这四张美术规格卡不进 Demo 预算。

## 校验器强制的东西

`node validate_chain.js` 不只查格式——它**强制设计文档里自己定下的约束**：

| 检查 | 来源 |
|---|---|
| 每题落位池 **2–4** 个 | 8.2 |
| 至少 **3 条跨源拼合** | 4.2 / 8.2 |
| 遮挡状态必须被该题落位池允许 | 4.3（答案源的遮挡状态随机） |
| 每个题干有且只有一条答案链（双向） | 参照完整性 |
| 难度 / 答案类型 / demo 枚举合法 | 本文档 |
| 池中源必须存在于 `sources.csv` | 参照完整性 |

**另外还有一层只有原型才查的东西**（`Tools/APlusProto/APlusProto.exe data`）：

| 检查 | 为什么 JS 校验器查不了 |
|---|---|
| **Demo 落位可达性**（上面的硬规则） | 需要知道每个源的 `demo` 值，JS 版没做 |
| **`cross_source` 必须是已知源 id** | ditto |
| **`occlusion_ids.csv` / `enum_labels.csv` 覆盖完整**（中文名都有 ASCII id） | 跨到新文件，JS 版不知道它们存在 |

### 它已经抓到过的真实问题（共 6 个，全部已修）

1. **`q.fill.07`（挂钟 vs 广播）只有 1 个落位池** —— 因为「广播」没被建模成答案源。修法是把 `broadcast` 加进 `sources.csv`，而不是放宽规则。
2. **手机通道只有 3 道独占题** —— 修法是补 `phone_outbox` / `phone_album` 两个源，并把时事类题改成手机独占。
3. **`risk=最高` 越界** —— `sources.csv` 用了设计文档 4.2 枚举里没有的一档（原型报 4 条错误）。
4. **`q.fill.20` / `q.fill.21` 在 Demo 里没有合法落位** —— 见上面的「Demo 落位可达性」。
5. **`eraser` 被建模成答案源却不在任何落位池里** —— 3000 轮从未被抽中，等于白做。已让 3 道新题把 `eraser` 放进池，答案限定为「你会抄在橡皮上的东西」。
6. **`q.fill.23` 的 `cross_source` 夹带说明文字、没有 id** —— 已改为 `paper_self` + 说明进 `notes`。

## 抽题：每轮 8–10 道怎么抽

1. 从题库里抽 8–10 道（`demo=y` 优先，**且落位池会过滤掉 `demo=n` 的源**）；
2. 按 `difficulty` 分配（`mix` + 分配模式，见下）；
3. 每题的答案源从 `pools` 里**随机抽一个**；
4. 该源再按 `occlusions` **随机抽一个遮挡状态**（或无；`noOcclusionProbability = 0.45`，实测约 29% 的题带遮挡）；
5. `answer_type=动态` 的题，答案按轮次/年份系统重新计算。

**第 3、4 步就是 4.3 的「三层随机」**——随机的是**落位**，不是题目本身。题目是手写的（含恐怖文本），**不程序生成**。

### 推荐参数（实测标定，见 `../../Docs/难度配比标定.md`）

| 每轮题数 | `mix`（易,中,难） | `mode` | `jitter` |
|---|---|---|---|
| 8 | `3,3,2` | `jitter` | 1 |
| **9（默认）** | **`3,3,3`** | **`jitter`** | **1** |
| 10 | `3,4,3` | `jitter` | 1 |

> **不要用固定配额（`quota`）**：实测它让每轮难度组成**逐字相同**（每轮易题恒为 3，偏差 0.0），
> 这恰好就是「每轮手感一样」。加权不配额（`weighted`）则波动过大（易题数能落到 0 或 8）。
> `jitter 1` 让每轮在 2–4 之间浮动，而难度预算仍受控（0 轮欠配）。
