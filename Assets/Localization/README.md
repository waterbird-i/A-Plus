## 最重要的一条：语义文本 vs 呈现文本

**不是所有文字都该进这张表。**

| | 进 String Table（**语义文本**） | 进字体／贴图资产集（**呈现文本**） |
|---|---|---|
| 是什么 | 「意思」会被读到的字符串 | **文字本身就是美术**的那些 |
| 例子 | `rules.csv` 的规则条目、`sms.csv` 的短信正文、`broadcast.csv` 的广播词 | 试卷抬头的印刷体、规则墙的粉笔字、记名册的**手写笔迹**、点阵短信的像素排版 |
| 为什么 | 它的「意思」要能被替换 | `第 三 次 模 拟 考 试` 的**等宽方块排版**、`字迹和你的一样` 这个恐怖点——**换不了字符串，只能换资产** |

所以 `paper.header.count_fmt` 只是**语义占位**：真正的抬头是预排版贴图，而 `max_chars` / `lines` / `font_variant` 三列就是给它的参数。

**字体槽位已决策**：四个槽位 + 一个隐性界面槽位的中英方案、授权风险与退化方案见 **`../../Docs/字体决策.md`**。
要点：手写槽位**不做字体、做笔迹资产**（因为 2.5.3 / 2.6 需要「可改一个字」与「三套笔迹」）；
点阵槽位**自建精简字模**（现成开源点阵字体多源自 JIS 字形，与大陆 GB 写法不一致）。
⚠️ **所有字体的授权状态一律需在发布前核实** —— 该文档没有断言任何一条授权。

## 世界内英文（A）填 `src`，不填 `en`

`world_en.csv` 里的英文**不是翻译**——它本来就是世界内的原文（英语科的卷面、听力、一条英文的隐藏规则）。
所以它走 `src` 列，`en` 列对它永远是空的。

**成本护栏：这些英文由中文作者按教材腔写即可，不需要母语者。** 中国高中英语题本来就是教材腔（Li Hua / Dear Peter / the Students' Union），**它越像练习册越真实**。

## 编码

- **UTF-8 with BOM**，**CRLF**。BOM 是为了 Excel / WPS / PowerShell 打开中文不乱码；Unity 的 `File.ReadAllText` 会自动吃掉 BOM。
- 含半角逗号的字段必须用双引号包住（`death.curve.note` 就是例子）。
- ⚠️ **必须是 CRLF + BOM，两者都要。** 本项目已经因为「无 BOM」损坏过两个文件：
  **PowerShell 的 `Get-Content` 在没有 BOM 的文件上会按系统 ANSI（中文 Windows 上是 GBK）解码**，
  而 GBK 是双字节编码，会把紧随其后的**换行也当成尾字节吃掉** —— 于是文件既乱码又丢行结构。
  **改这些 CSV 请用编辑器或 Node，不要用 PowerShell 的 `Get-Content`/`Set-Content` 往返。**
  原型自检里有一条 `every csv carries a utf-8 BOM` 守着；`validate.js` 也会对缺 BOM 报警告。

## 校验

```
node validate.js
```

检查项：文件 BOM · 表头一致 · 每行列数 · `key` 唯一且命名合规 · `src` 非空 · 枚举合法 · 数字列格式 · `max_chars` 超长（警告）· `en` 列意外填值（警告）。

## 怎么加一行

1. 在对应表末尾加一行，`key` 用小写点分；
2. `register` 必填；
3. 若这段文字**本身是美术**，不要只加字符串——同时记下需要的字体／贴图变体；
4. 跑 `node validate.js`；
5. 若这一行和某个机制咬合（例如 `rule.wall.05` 与「异视必须抬头」冲突），在 `note` 里用 ★ 标出并引用设计文档章节。
6. **题干（`q.*`）还要在 `../Data/answer_chain.csv` 里加一条答案链**，否则 `validate_chain.js` 会报「题干没有对应的答案链」。两个校验器都要跑。
